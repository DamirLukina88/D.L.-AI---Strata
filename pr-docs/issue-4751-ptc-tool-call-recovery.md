## Title
[Engine] Programmatic tool calling (PTC) prefix and spaced alias normalization
Issue: Resolves #4751

## Summary
Prevents tool calls from being emitted as plain text / rejected when generated by models in programmatic tool-calling (PTC) mode or formatted with namespaces. Normalizes tool prefixes such as `tools.<name>`, `functions.<name>`, `default_api.<name>`, space-separated forms like `<function=tools name>`, and resolves bare prefixes to single-match declared tools.

## What changed
- `serve/frontend.py`:
  - Extended alias map creation in `OutputParser.__init__` to automatically register canonical prefixes (`tools.`, `functions.`, `default_api.`) pointing to declared tool names.
  - Implemented `_prefixed(fresh)` in `OutputParser` to rewrite spaced calls (`<function=tools NAME>`) into `<function=NAME>`.
  - Added bare prefix resolution (`<function=tools>` / `<function=functions>`): when `tool_call_recovery` is active and exactly one declared tool matches the provided parameter signature, the call is mapped to that tool.
  - Added lookahead buffer `_PREFIX_PART` to prevent partial prefix arrivals from leaking text across streaming delta chunks.
- `serve/test_tool_name_prefix.py`:
  - Added comprehensive test suite testing single-token, chunked, and full-stream arrivals across all supported prefixes.
- `serve/test_history_tools.py`:
  - Added test case verifying multi-turn conversation histories preserve normalized tool names.

## Extra Notes
- **Precedence guarantee**: An exact declared tool name (e.g. a tool explicitly named `tools`) always takes precedence over prefix stripping.
- **Verification**:
  ```bash
  python3 -m unittest serve.test_tool_name_prefix -v
  python3 -m unittest serve.test_history_tools -v
  ```
  Passes all tests without regressions.
